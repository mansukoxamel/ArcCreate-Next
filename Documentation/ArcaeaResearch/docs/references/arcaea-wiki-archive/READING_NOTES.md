# Arcaea Wiki 技術資料 読解記録

## 目的と範囲

調査日: 2026-09-05

Arcaea Wiki全ページ一覧1,424件から、ゲーム仕様、譜面、判定、計算式、譜面定数、ポテンシャル、遅延、World／Course、各種一覧と変更履歴に該当する124ページを抽出し、本文を通読・保存した。

曲ごとの攻略、コメントページ、ストーリー本文、画像・動画本体は対象外とした。これはサイト全体の完全複製ではなく、譜面制作と仕様確認に使う技術資料集である。保存範囲の正確な一覧、原文URL、本文ハッシュは[manifest.json](manifest.json)を参照すること。

本文HTMLは[pages](pages)に、横断検索用の結合テキストは[all_pages.txt](all_pages.txt)に保存した。`Daily Top 100`はJavaScriptで内容を生成するページで、取得した`#content`には本文がなかった。取得失敗として隠さず、既知の本文なしページとしてmanifestに記録している。

## 資料としての位置づけ

- Arcaea Wikiはコミュニティ編集の二次資料であり、本家の公式仕様書ではない。
- ページ内にも「要検証」「可能性が高い」「条件不明」と明記された箇所がある。それらを確定仕様に格上げしない。
- バージョン更新で変わる仕様と、旧バージョン専用の計算式が同じページに併記されている。式を使う前に対象バージョンを確認する。
- AFFの文字列表現は、実物AFF 1,478件の調査結果を優先する。このWikiは主にプレイヤー側のゲーム仕様を補う資料として使う。

## 譜面制作に直接関係する確認事項

### 判定とスコア

総ノーツ数を`N`、EARLY/LATE付きPURE一個の基礎点を`P`とすると、Wiki記載の式は次のとおり。

```text
P = 10,000,000 / N
FAR = P / 2
LOST = 0
無印PURE = P + 1
```

コンボボーナスはない。したがって、全ノーツを無印PUREにした理論値は`10,000,000 + N`となる。

タップ対象の判定幅は、無印PUREが±25ms、EARLY/LATE付きPUREが±50ms、FARが±100msと記載されている。ロングノートとアークノートは無印PURE／LOSTのみ。トレースノートは操作、判定、スコアの対象外である。

「FARを一個だけ出して残りを無印PUREにしても10,000,000点を超える」条件は、次の不等式になる。

```text
10,000,000 - 5,000,000 / N + (N - 1) > 10,000,000
N(N - 1) > 5,000,000
```

最小の整数`N`は2,237。ただし保存時点の記述では、ver.7.0.1までに2,237ノーツ以上の譜面は存在しない。

### ノート種別の実プレイ上の性質

- フロアノートとスカイノートは時刻に合わせてタップする。
- ロングノートは途中から拾い直せる。
- アークノートには始点タップ判定がなく、前もって指を置くこともできる。途中から拾い直すこともできる。
- アーク／ロングの保持中に判定点が存在する。単純な「一イベント＝一ノーツ」とは限らないため、AFFイベント数とゲーム上の総ノーツ数を同一視しない。
- トレースノートはスカイノートの予告や演出に使われるが、判定やスコアには加算されない。

### ノーツ密度

一覧ページでは、ノーツ密度を次の式で算出している。

```text
ノーツ密度 = ノーツ数 / 演奏時間（秒）
```

これは曲全体の平均であり、局所的な発狂や同時押しの難しさを表すものではない。

## ポテンシャルと譜面定数

### 現行記載（ver.7系）

Best枠は譜面別ポテンシャル上位50譜面で、上位10譜面を2倍に重み付けする。したがって実質60譜面分の平均となる。Recent枠はver.7.0.0で廃止された。旧Recent枠の説明や旧計算式は履歴資料であり、現行計算へ混ぜない。

表示ポテンシャルは小数第3位までで第4位以下切り捨て。内部計算はさらに細かい桁を使う可能性が高い、という検証上の注記がある。

譜面定数を`C`、スコアを`S`とした譜面別ポテンシャルの記載は次のとおり。

```text
S >= 10,000,000:
    C + 2.0

9,800,000 <= S <= 9,999,999:
    C + 1.0 + (S - 9,800,000) / 200,000

S <= 9,799,999:
    max(0, C + (S - 9,500,000) / 300,000)

TRACK COMPLETE:
    上記へ +0.2
```

EASYスキル時の`+0.2`適用についてはページ自身が「要検証」としている。

主要点は、10,000,000点で`C+2.0`、9,900,000点で`C+1.5`、9,800,000点で`C+1.0`、9,500,000点で`C`となる（TRACK COMPLETE補正を除く）。

### 関連計算

```text
プレイ結果 = 2.5 + 2.45 * sqrt(譜面別ポテンシャル)
ステップ値 = プレイ結果 * パートナーSTEP / 50 + パートナースキル
獲得経験値 = 譜面別ポテンシャル * 6
```

ワールドモードの表示STEPを用いる旧来の譜面定数推定法として、AA以下かつTRACK LOST、表示STEPが2.5より大きい場合に次の式が掲載されている。

```text
譜面定数 = ((STEP - 2.5) / 2.45)^2 - (スコア - 9,500,000) / 300,000
```

ただし表示STEPは小数第1位より下を切り捨てるため、表示値以上・表示値+0.1未満の範囲で誤差を評価する必要がある。

Arcaea OnlineのBest枠画像から、TRACK COMPLETE済み譜面の定数を逆算する記載は次のとおり。

```text
PM:    譜面別ポテンシャル - 2.2
EX以上: 譜面別ポテンシャル - 0.2 - (スコア - 9,600,000) / 200,000
AA以下: 譜面別ポテンシャル - 0.2 - (スコア - 9,500,000) / 300,000
```

## World関連の計算

通常Worldのパフォーマンスレートについて、譜面別ポテンシャルを`P`、マップ定数を`M`とすると次の式が掲載されている。

```text
パフォーマンスレート = (2.5X + 2.45 * sqrt(P)) / M
X = 3（TRACK COMPLETE以上）または1（TRACK LOST）
```

表示値が小数第2位までの場合、マップ定数の推定範囲は次のように示される。

```text
最小M = (2.5X + 2.45 * sqrt(P)) / (表示レート + 0.01)
最大M = (2.5X + 2.45 * sqrt(P)) / 表示レート
```

Beyondゲージ増加量は次の式。

```text
Beyondゲージ増加量 = 2.7 + 2.45 * 譜面別ポテンシャル
```

World Parallelのシンクブーストは次の式として掲載されている。

```text
シンクブースト = 1 + 全員のスコア合計 / 人数別係数
係数 = 200,000,000（2人）、100,000,000（3人）、80,000,000（4人）
最大 = 1.1（2人）、1.3（3人）、1.5（4人）
```

ただし2人・3人では式と異なる場合があること、その条件は保存時点で不明であることが明記されている。確定式として実装しない。

## 想起率

通常ゲージで1 PUREあたりの増加量を`a`、総ノーツ数を`N`とした基本式は次のとおり。

```text
N < 400:       a = 0.2 + 80 / N
400 <= N < 600: a = 0.2 + 32 / N
600 <= N:      a = 0.08 + 96 / N
Level 11以上:  a = (0.08 + 96 / N) * 0.8
```

Level 11以上の補正は「ほとんどの譜面」と書かれており、全譜面への一律規則とは断定できない。パートナースキルにも多数の例外があるため、想起率計算器を作る場合は別途、実測とバージョン別検証が必要。

## 遅延調整とAudioOffsetを混同しない

Wikiの「遅延調整」はプレイヤー端末の音声設定で、`+`／`-`が0.1刻み、`<`／`>`が1.0刻みと説明されている。報告値は端末、OS、スピーカー／ヘッドホン、効果音の有無、プレイ姿勢、個人差に依存する投稿データである。

これはAFFヘッダーの`AudioOffset`ではない。MAGATU TEMPO FORGEで曲と譜面時刻を合わせるための`AudioOffset`や、WAV先頭への無音追加によるゼロ化の判断根拠へ、端末別遅延値を転用しない。

## MAGATU TEMPO FORGEへの反映判断

今回の資料から、AFFの`timing(...)`表記やBPMの保存桁数に関する新しい反例は得られていない。正式AFF出力規則は[AFF_FORMAT_RESEARCH.md](../../../AFF_FORMAT_RESEARCH.md)に記録した実物1,478譜面の観測結果を引き続き基準とする。

有用なのは次の補助情報である。

- タイミング調整結果の試験時、±25ms／±50ms／±100msというプレイ判定幅を目安に誤差を評価できる。
- アーク始点はタップ判定を持たないため、波形のアタックと視覚上のアーク始点を同じ意味で扱わない。
- 既存AFFから総ノーツ数を求める場合、イベント行数ではなくロング／アークの判定点を含むゲーム側の数え方が必要。
- ポテンシャル、譜面定数、World計算は譜面出力形式とは別層の仕様であり、テンポマップ生成に混ぜない。
- Wiki記載のBPM一覧は曲情報の参考にはなるが、可変テンポ区間の正確な開始msを確定する資料ではない。実音源と実物AFFを優先する。

ロング／アークの内部判定点については、Wikiの公称総ノーツ数をArcCreate／Arcade Plusの実装と実物AFFへ突き合わせた[AFFノート構造・判定点 調査記録](../../../AFF_NOTE_JUDGEMENT_RESEARCH.md)を参照すること。

## 再取得方法

リポジトリ直下で次を実行する。

```powershell
python tools/archive_arcaea_wiki.py
```

スクリプトは`requests`と`beautifulsoup4`を使用する。既存HTMLは再利用し、新規ページだけ7秒間隔で取得する。HTTP 429では待機して再試行する。再取得後は`manifest.json`のページ数、既知でない空本文、本文ハッシュを確認する。
